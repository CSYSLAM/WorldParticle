# 减少同步与重复运动学计算

本轮优化 `--execution-policy fused_graph`。2026-11-21 起，机器人入口默认采用 `auto`：CUDA 的 Franka 软块、单角抓布和 W1 装袋自动启用 `fused_graph`，CPU 与其余三个场景使用 `reference`；显式指定策略仍优先。模型仍为 v24 cloth40 的 648 维共享主干、46,884,109 个有效参数，权重没有更新。名义三子步、每子步两轮解析预测和一次网络调用，W1 原来的自适应细分与所有物理接受条件保留。网络 FP32、物理 FP64。

## 具体改动

1. **拓扑只计算调用者需要的数据。** 两个物理接受分组入口只消费连通组标签，原来仍生成所有关系槽位的动态索引。现在这两个入口跳过槽位构建；网络拓扑入口继续保留完整槽位。已有 CPU 并查集仍按原行顺序执行，世界节点、固定节点和批次隔离规则保留。合法的 CUDA 整数元数据合并成一次 int64 传输，避免多次标量等待和单独的列表复制；大整数 ID 不经过浮点数。
2. **合并接触激活上界检查。** 有限性、非负余项/刚度以及结果溢出标记在纯 GPU 算子内一起计算，一次取回三个标记，保持原来的报错优先级和曲率公式。该纯算子加入有界图清单，碰撞检测、接受决策和历史提交仍实时执行。
3. **按现有 compact 约定省去诊断值复制。** 仅在 `fused_graph` 且场景启用 `compact_numerical_diagnostics` 时，接触激活缩放的详细诊断值标为 `values_omitted`。实际缩放、有限性检查和物理数据保留。详细诊断模式仍输出原内容。
4. **接入现有单步运动学缓存。** 只复用同一个网络物理步内、源张量身份及版本均未变化的纯几何结果。缓存不保留力、残差、材料响应、接触历史或接受决定，每物理步结束清空；最多 256 项/32 MiB，强引用和视图的完整底层存储计入预算。状态或几何源修改后重新计算，梯度开启及无版本张量跳过缓存。

```mermaid
flowchart LR
  A[当前状态与接触] --> B[单步内纯运动学复用]
  B --> C[解析预测与共享网络]
  C --> D[当前能量与接触检查]
  D --> E[合并检查标记传输]
  E --> F[CPU 接受决定与历史提交]
  F --> G[清空单步运动学缓存]
```

这仍是网络和物理协同求解。本轮没有压缩网络、减少调用次数、减少接触行、放宽任务门槛或调用完整 VBD/Featherstone。图的特化预算与算子级超限处理沿用 v29。

## 测时口径修正

复核发现旧 Franka 保持帧脚本每个子步调用一次控制器，正式 demo 为每三子步一次。`benchmark_robot_step.py --frame-loop` 已修正，并在每个样本记录/检查控制器调用数。旧 v29 的 2.25 FPS 属于旧脚本频率；其正式完整 270 帧录制不受这个问题影响。不同轮次、不同控制频率与不同后台负载的 FPS 不宜直接相除。

当前脚本的 `fused_graph_legacy` 消融项采用本轮改动前的图计算配置，不启用新的合并检查和运动学缓存；`fused_graph` 同时启用。交错样本重置到同一份已接受的模型状态和历史，使用相同控制目标及权重。Franka 短窗包含一次控制器、三个物理步和内存记录；抓布/W1 短窗仅包含三个求解器物理步。

七样本交错测试的中位数如下，每个样本都是三个物理步/三次网络调用。Franka 为保持帧循环，另外两例仅为求解器短窗；不能将三组直接换算为完整 demo FPS。

| 场景 | 原图配置秒 | v30 秒 | 耗时降低 |

| franka | 0.4496 | 0.4401 | 2.1% |

Franka 保持段约 2.27 FPS；其配对样本中有一次变慢约 14.8%，其余试验及原始样本保留，不能据中位数声称每帧都提速。抓布和装袋的七组配对样本均有小幅收益。

正式 CLI 的三例完整 GPU 回放均通过原任务检查、零重试：

| 场景 | 帧数 | 网络调用 | 原任务检查 | 录制循环 FPS |
|---|---:|---:|---|---:|

Franka 保持期间软体最低离桌约 113 mm，最大机器人/软体表面重叠约 0.147 mm，最小四面体体积比为 0.660。抓布末段宽度比为 0.599，原门槛为 0.55，折叠方向一致性检查也通过。W1 末段检查的方块角点均在实际袋壳内（沿用 2 mm 接触容差），抓持采样双侧接触比例为 100%，可见变形检查通过。W1 原有自适应细分使实际调用略多于 288×3。

这些完整计时包括循环内首次编译、控制、碰撞、检查及记录，不完整包含前置初始化，也不包含视频渲染；上一例的 CPU 审核/渲染可能与下一例推理重叠，不能用于计算对历史版本的受控提速比。三例的完整严格数值回归均为 FAIL。

完整任务检查与严格数值回归分别报告。GPU 并行归约顺序仍可改变长轨迹，短窗一致不等于完整轨迹一致；简单抓布尚无自接触，原有展开外观波动也不因性能优化自动解决。其余三个机器人 demo 本轮没有完整验收。

## 使用

```bash
cd /home/oem/code/worldparticle
export WP_VBD_NEWTON_ROOT="$PWD/.local/newton_pinned_25298"
export TORCHINDUCTOR_CACHE_DIR="$PWD/.local/p0/torchinductor"

# 完整 GPU 推理并离线渲染；scene 也可选 cloth / w1。
.venv/bin/python scripts/run_robot_validation.py --scene franka \
  --execution-policy fused_graph --output outputs/my_v30_franka --render

# 开窗观察：加 --window；首次预热不代表稳定帧率。
.venv/bin/python scripts/run_robot_validation.py --scene cloth \
  --execution-policy fused_graph --window

# 同条件前后对照；输出目录须不存在。
.venv/bin/python scripts/benchmark_robot_step.py --case franka \
  --recording outputs/current_weight_demos_20261120/recordings/franka_soft \
  --output .local/my_v30_benchmark --frame-loop --repeats 7 \
  --variants reference fused_graph_legacy fused_graph
```

行容量分组、直接稀疏 Triton 作用和注意力图回放也进行了独立试验：收益不稳定或不足，未接入本轮策略。后续需要继续定位 CPU 发射/等待和小算子调度，而不是从这次小幅改进推断已实现实时。

## 默认入口与下一步（2026-11-21）

三个已验证场景的统一入口及各自直接入口均已接入自动选择，批量入口按场景分别选择，并在每个任务中记录实际策略。Franka 直接入口的 duck / rigid_cloth 资产以及离线原生 VBD 默认使用 reference。纯几何预览使用 CPU 策略；训练与通用求解器的默认配置没有修改。上面的完整回放使用显式 fused_graph，默认选择的修改没有改动那些物理算法与权重。

```bash
# GPU 默认已启用，无需额外传 fused_graph。
.venv/bin/python scripts/run_robot_validation.py --scene franka --window

.venv/bin/python scripts/run_robot_validation.py --scene franka --execution-policy reference

.venv/bin/python scripts/run_robot_validation.py --scene w1 --device cpu
```

默认选择、统一入口的 GPU/CPU 命令生成、显式覆盖、离线原生 VBD 默认和直接入口解析已验证；训练与配置作用域检查也通过，见 [默认入口检查](../outputs/inference_defaults_v30/selection_checks.json)。本次只修改默认策略选择，没有重复运行上一轮已完成的完整 GPU 回放。原始源码快照与 source_validation 保留的是当时显式策略验证时的状态，不代表后续默认入口修改后的源码哈希。

下一轮先优化计算图和完整循环，再考虑减少解析预算：

1. 用当前 v30 的实际状态重新分段测时，分别记录网络、接触几何、解析/粗空间、接受检查、控制/记录与首次编译；使用相同负载交错比较完整循环，避免用网络前向吞吐或单个保持状态替代完整推理效率。
2. 首先研究合并接触几何和响应装配的连续纯张量区域：坐标变换、端口几何/雅可比、接触度量及其作用。尽量让中间状态留在 GPU，将必须回到 CPU 的检查标记合并；仍保留当前物理条件、FP64 与实际输入更新。先用算子对照检查与消融验证收益，再做三例完整任务和视频验收。此前无稳定收益的简单行填充分组不直接复用。
3. 在同一版中检查其余三个场景的完整 GPU 任务，通过后再扩大自动启用范围。完整录制耗时、启动成本、显存和任务效果分开报告，七样本短窗的 2%～4% 不能当成完整任务提速保证。
4. 工程开销下降后，再评估把每子步两轮解析预测减少为一轮，并以大网络学习剩余补偿。该项是后续训练研究，需要生成相应少解析轮数/较大步长的数据和滚动监督；先保留当前 A2+N1 基线独立对照，不能只在推理时删掉一轮解析或直接放大步长。
