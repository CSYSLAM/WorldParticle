# 第三轮推理执行优化：稀疏响应、拓扑映射和小矩阵融合

本轮候选执行策略为 `fused_device`，默认仍为 `reference`。继续使用 v24 / cloth40 权重，SHA256 为 `1aac9909419fbb8dda7beef4f0d533050d4ce4191849ebd54ba37dd6a85a2132`；648 维共享主干、46,884,109 个活跃参数均保留。名义每帧三子步，每子步两轮解析预测和一次网络校正；W1 装袋保留原自适应细分。没有训练更新或原生 VBD/Featherstone 回退。

## 实现

- 网络层级规划批量读取对象编号和类型，保留原来排序、分组和合并轮数。该改动单独的实测收益不到 1%，不把大量标量调用自动等同于主要耗时。
- 编译原来的稀疏 `Jᵀ W J` 作用、对角组装、两遍修改 Gram–Schmidt、粗空间作用，以及关节子树运动列与 mimic 投影。仍按原顺序处理 owner 和列，保留原秩阈值、固定自由度及有效性判定。
- 粗空间拓扑使用批量数组映射。版本化索引缓存保留输入引用，并检查原地修改；新分配但内容完全相同的索引可用不可变的完整内容键复用映射。最多 128 条、16 MiB，计入输入背后的完整存储。只缓存索引，不缓存力、Jacobian、度量、状态或网络响应。接触活动变化但分区相同时，复用相同成员索引，布局代数仍更新。
- 运动包络、端口有限性/姿态检查和剩余运动步长计算合并计算。原来的查询预算、首个可接受候选、材料路径检查及拒绝规则均保留。
- 诊断值先保留为 GPU 张量，在记录器边界按类型批量复制，临时拼接缓冲最多 8 MiB。整数与布尔值不经浮点中转；嵌套报告仍是数值/列表，不写成张量字符串。
- 小矩阵优化通过单次编译的 `CustomGraphPass` 选项启用，没有修改已安装库或全局替换库函数。只分解能证明尺寸足够小的 CUDA FP64 MM/BMM；未知尺寸、其他精度和非默认缩放的 addmm 保留原算子。编译后可与周围逐元素计算融合，避免每个小矩阵都发射独立算子。

神经网络仍为 FP32，物理计算仍为 FP64。快速路径继承 `fused_fast` 的普通 GPU 并行聚合及关闭未初始化内存调试填充，因此不能承诺逐位复现。所有实际有限性、接触和变形检查都保留。编译模式只在物理调用期间生效，形状特化预算在该范围从默认 8 提升为 32（尊重调用者已有的更高预算），退出/异常后恢复；不通过补零或删除粗空间列来减少形状变化。

这些推理 CLI 使用独立进程；PyTorch 算术设置属于进程全局状态，不应在同一进程并发运行不受控的训练线程。梯度开启时保留原训练路径。CPU 仍负责控制、索引规划、调度和记录；这不是全流程完全留在 GPU 的实现。

```mermaid
flowchart LR
    A[资产 / 材料 / 控制目标] --> B[GPU 碰撞查询与状态读入]
    B --> C[索引版本 / 完整内容检查]
    C --> D[复用拓扑映射]
    D --> E[GPU 解析预测与共享网络]
    E --> F[融合稀疏作用 / 小矩阵 / 投影]
    F --> G[原运动 / 接触 / 材料路径与能量检查]
    G --> H[提交接受状态与历史]
    H --> I[记录时批量复制诊断]
```

## 验证及局部测时

CPU/GPU 检查覆盖了重复 owner 的稠密能量对照、投影能量正交性、冗余及零列秩、固定自由度、非法度量拒绝和训练梯度。索引测试覆盖同尺寸重排、原地修改、移动性改变、缓存逐出、大存储视图和无版本输入。运动测试覆盖原来的所有射线尺度、包络以外状态、非有限更新、非法半径及全固定场景。诊断测试包含非连续视图、空张量和超过浮点精确整数范围的 int64 编号。真实 Franka 关节树检查包含结构/mimic 方向误差、坐标规范协变性、正性和循环树拒绝。

独立小矩阵检查包含 FP64/FP32、非连续矩阵、空 batch，以及 addmm 的非默认 alpha/beta。编译和算术作用域的嵌套、异常恢复及梯度开启的训练路径均单独检查。原始结果保存在 `.local/inference_speed_v27/`。

每策略七个交错样本，同进程、同接受状态和历史；每样本三个真实物理步、三次网络调用、零重试。Franka 包含原控制器、关节读出和逐帧内存记录，是保持阶段的帧循环；布和 W1 是保持状态的求解器短窗。硬件 RTX 5090 D v2，PyTorch 2.7.1 / CUDA 12.8；没有暂停其他目录的作业。

| 采样 | reference 秒 | fused_fast 秒 | fused_device 秒 | 对 fused_fast 的耗时降低 |
|---|---:|---:|---:|---:|
| Franka 保持帧循环 | 1.2223 | 0.6698 | 0.5656 | 15.6% |
| 抓布求解器短窗 | 1.0561 | 0.5914 | 0.4936 | 16.5% |
| W1 装袋求解器短窗 | 1.6114 | 0.8781 | 0.6641 | 24.4% |

这是热运行局部测时，不是完整任务或开窗 FPS。中间实验发现，仅融合稀疏作用/正交化约有 1% 收益，索引优化也不能单独解决整体速度；cProfile 会放大 Python 扫描的开销，不能用带插桩的时间推断实际加速。最终结果以未插桩交错测时和完整回放分别报告。

## 完整任务验收

六例首次完整回放共 1602 帧、4819 次网络调用，均零重试。五例通过原任务检查；抓布首次展开宽度比为 0.549157，略低于原 0.55 门槛，其余抓取、离桌、面积、拉伸和重叠检查通过。六例严格逐帧数值回归均未通过，不声称轨迹数值等价。

| 场景 | 完整推理 FPS | 原任务检查 |
|---|---:|---|
| Franka 夹软块 | 0.849 | PASS |
| W1 装袋 | 0.868 | PASS |
| Franka 抓布 | 1.085 | FAIL：展开宽度 |
| Piper 软块放刚体 | 1.077 | PASS |
| W1 双手夹取 | 1.065 | PASS |
| Franka 刚体放布 | 1.027 | PASS |

完整 FPS 取各 runner 记录的整段 `wall_seconds`，包含控制、惰性形状编译与记录，不含离线视频渲染。前置导入、资产构建和模型装载并未统一完整计入，因此也不是程序启动到退出的总耗时；使用已有编译磁盘缓存，不是清空缓存后的首次安装性能。运行时还存在软件渲染等后台负载，因此不能用历史 FPS 比值推断受控加速。实际仍约 1 FPS，尚未实时。

对抓布另外做了两条完整诊断：保留长内积原算子的隔离版本宽度比 0.559780（PASS），原候选不改代码再次运行为 0.652608（PASS）。这三个样本不能确定长内积改写是原因，也不能证明快速归约下的外观稳定性。原失败回放保留，不用重跑覆盖；原门槛不变，`fused_device` 仍为可选候选策略，未提升为默认。三个诊断的机器人/布最大重叠分别约 0.50 / 0.37 / 0.41 mm。

原六例视频、审计、严格数值对照与抓布重复性记录见 [本轮结果目录](../outputs/inference_speed_v27/README.md)。人工检查了六个末帧和抓布时间线接触表，视频解码帧数已核对；没有声称逐帧观看全部视频。W1 双手最初因延迟诊断张量未转换为 JSON 数值而中断，修复记录器后从头完整重跑；失败前缀不计入成功回放 FPS，故该 FPS 不是包含失败尝试的总实验吞吐率。

## GPU 时间线与下一步

同一个 Franka 保持状态的三个物理步，最终 Nsight 对照结果如下。插桩会增加耗时，这里只用于定位，不代替上面的无插桩测时。

| 指标 | reference | fused_fast | fused_device |
|---|---:|---:|---:|
| GPU kernel 数量 | 213133 | 71106 | 57944 |
| kernel 时间之和，ms | 480.3 | 167.4 | 138.2 |
| 设备到主机拷贝次数 | 2506 | 2380 | 1931 |
| 其中不超过 8 字节 | 2350 | 2224 | 1810 |

共享网络本体在该窗口的 kernel 时间之和约 7.64 ms，物理投影、组装、候选检查与 CPU 提交间隙仍占主要开销；这不代表网络对最终状态不重要。嵌套 NVTX 区间不能相加，kernel 时间之和也不是硬件利用率。CPU 全量替代的短窗实验比当前 GPU 路径慢，没有据此切换计算设备。

另做了跳过废弃局部弹性/阻尼矩阵的隔离实验，保留完整物理残差和实际使用的稀疏度量。CPU/GPU 的残差、有效度量、默认训练梯度均精确一致；五样本交错测时中，Franka 和布的两组中位数收益为 0.48% / 0.79%。W1 两组中位数收益为 6.26%，但原路径包含一次 2.0565 秒慢样本，逐轮配对收益中位数只有 0.93%；该小样本结果不足以确认稳定收益。实验保存在 `.local/inference_speed_v28/`，未合并到正式策略。

下一项隔离实验是 CUDA Graph，先评估固定形状物理算子的发射开销。实验保留图输出的独立副本，避免下一次回放覆盖仍在使用的度量和状态，并检查不同接触形状及显存占用。原代码尚未启用该路径。后续再把剩余的小标量判定尽量合并到设备端，保持候选选择次序、接触与材料检查。抓布的外观重复性仍是候选升为默认之前要解决的问题。

CUDA Graph 若在保持状态短窗有收益，下一步仍需验证接触数量变化、接触集合重排、粗空间列数变化、固定/移动对象变化和历史提交；图复用必须以真实输入和形状为准，不能重放旧接触或旧物理状态。还需设置缓存/显存预算并完整复跑场景。短窗图回放通过不等于完整任务已支持，也不能绕过 CPU 侧仍在决定的物理接受条件。

隔离的第一版图实验在 Franka 七样本保持帧循环中从 0.5768 秒降到 0.4697 秒（耗时减少 18.6%），但随后完整流程在第 4 帧后触发特化缓存上限而失败，未用于正式代码。已另做数量受限的原型：图编译使用独立代码对象，避免占用原编译算子的缓存；每函数最多八个特化，达到上限后仅该纯算子改用当前输入的原编译计算。它不调用传统求解器，也不绕过物理检查。故意把上限降为两个特化的测试已验证超限后可继续、结果一致、旧输出保持有效以及配置作用域恢复。修正版的完整流程和速度需要重新测量，第一版短窗加速不能直接移植为修正版的性能结论。
